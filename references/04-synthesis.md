# Шаг 5 · Допрос данных: GAP, концепты, решение

Задаём вопросы собранным исследованиям и проверяем, на чём основаны ответы. Результат — 1–3 гипотезы продукта с обоснованием на данных и понятным следующим тестом.

## Правила сборки

В уроке этот промпт ставят в настройки чата Gemini Notebook. Здесь это твои правила для каждого ответа шагов 5 и 6.

```text
Ты - аналитик-верификатор. При ответе на любой вопрос:

1. Отвечай ТОЛЬКО на основе загруженных источников. Если информации нет - скажи прямо.
2. Если данные ПРОТИВОРЕЧАТ друг другу - укажи: "Источник A говорит X, источник B говорит Y. Требуется проверка."
3. Для каждого утверждения указывай конкретный источник.
4. Не додумывай, не склеивай противоречивые данные в "средний" ответ.
5. Для рекомендаций оцени качество и независимость источников. Совпадение ответов само по себе не доказывает факт; неподтвержденные выводы отмечай как гипотезы.
```

Как это читать здесь:
- «Загруженные источники» — файлы `research/reports/`, `research/sources/check.md` и страницы, которые ты открыл при проверке. Знания модели и новый поиск источниками не считаются.
- Источник утверждения — файл отчёта и номер ссылки в нём: `market-claude-2026-10-25 [4]`.
- Вывод опирается на пункт со статусом «не подтверждает», «недоступен», «пересказ» или «устарел» из `check.md` — помечай его «гипотеза». Статус «частично» — используй вывод только в границах фрагмента.
- «Не видно у конкурентов» — значит не нашли в изученных материалах. Это ещё не доказанный пробел рынка.

## GAP-анализ → `research/synthesis/gap.md`

```text
Проанализируй все загруженные источники и синтезы.

Составь детальный GAP-анализ:
1. ЧТО ДЕЛАЮТ ВСЕ конкуренты – базовый стандарт рынка
2. ЧТО НЕ ЗАКРЫВАЮТ – какие боли конкуренты игнорируют (моя возможность)
3. СЛАБЫЕ МЕСТА конкурентов – где теряют клиентов
4. ЯЗЫК КЛИЕНТА – конкретные фразы, боли, желания для маркетинга
5. ГОЛУБОЙ ОКЕАН – где пустое пространство для прорывного продукта
```

## Синтез гипотез продукта → `research/synthesis/concepts.md`

```text
На базе всех загруженных данных (исследование рынка, ЦА, конкурентов):

1. АНАЛИЗ ГЭПОВ: чего НЕ предлагают конкуренты, но на что есть спрос?
2. КОНЦЕПТ ПРОДУКТА: что именно мы продаем (конкретный формат)
3. ТОП-3 СЕГМЕНТА ЦА: кому продаем, ключевая боль, почему купят
4. ОФФЕР: обещание, которое закрывает главную боль
5. КИЛЛЕР-ФИЧА: одна особенность, которой нет ни у кого
6. БИЗНЕС-МОДЕЛЬ: как монетизируем

Дай 2–3 варианта концепта. Для каждого – обоснование на данных.
```

Каждый концепт, кроме шести пунктов промпта, закончи карточкой гипотезы:

```markdown
**Аудитория:** …
**Задача / боль:** …
**Продукт:** …
**Основания:** ссылки на отчёты и выводы из check.md
**Что проверить:** …
**Следующий тест:** …
```

Покажи концепты коротко: название, аудитория, боль, продукт, оффер, сила оснований **⏸**. Человек выбирает вариант — или просит доработать.

| Сила оснований | Когда |
|---|---|
| сильная | ключевые выводы концепта «подтверждает» в `check.md`, из двух и более независимых источников |
| средняя | подтверждена часть выводов или всё держится на одном источнике |
| слабая | концепт опирается в основном на гипотезы и неподтверждённые выводы |

## Выбираем продуктовую гипотезу → `research/synthesis/choice.md`

`[ВАРИАНТ X]` — вариант, который выбрал человек.

```text
Возьми [ВАРИАНТ X] концепта продукта.

Определи:
1. В каком сегменте выше коммерческий потенциал и какими данными это подтверждается
2. Какую ОДНУ боль мы решаем (фокус)
3. Сформируй оффер: [Результат] за [Срок] даже если [Барьер]
4. Ценный конечный результат для клиента
5. Почему это выстрелит – 3 аргумента на данных
```

Затем ответь в том же файле на вопросы урока «Уточняем коммерческий потенциал»:
- В каком сегменте выше коммерческий потенциал?
- Что подтверждает готовность платить?
- Какие данные могут опровергнуть нашу гипотезу?

Пробел мешает решению (например, о готовности платить нет ни одного источника) — предложи одно дополнительное исследование по этому вопросу **⏸**. Не больше одного раунда: дальше вопрос переходит в следующий тест. Как его провести:
- задание — короткое, только по пробелу, в `research/tasks/<слово>.md`; бриф исследователя тот же (`references/03-research.md`);
- отчёт — `research/reports/<слово>-claude-<ГГГГ-ММ-ДД>.md`, где слово — одно английское слово по сути вопроса: `price`, `demand`;
- ссылки извлеки, 3–5 ключевых выводов проверь и допиши в раздел «Дополнительно» файла `check.md`;
- допиши ответы в `choice.md`.

## Решение → `research/decision.md`

«Техника фрезеровщика»: одна аудитория, одна боль, один продукт. Аудитория + боль + продукт → гипотеза для теста.

```markdown
# Решение · версия 1 · <проект>

**Решение:** что проверяем
**Для кого:** аудитория; пометка «пока гипотеза», если сегмент не подтверждён
**Боль:** одна задача, которую решаем
**Продукт и оффер:** [Результат] за [Срок] даже если [Барьер]
**Основания:** ссылки, цитаты и данные из research/
**Что пока не знаем:** …
**Следующий тест:** интервью, пробное занятие, лендинг — с критерием успеха
**Условие пересмотра:** при каком результате теста меняем предложение
```

Предположения отмечай отдельно. Срок и результат оффера — гипотеза для пилота, а не обещание.

Критерий успеха и условие пересмотра данными не подтвердить: это решение человека. Предложи конкретные числа (например, «5 предоплат за 3 недели») с пометкой «предложение» и попроси человека утвердить или заменить.

Учебный пример из урока (решение ещё требует проверки данными):

```markdown
# Решение · версия 1 · Пилот обучения детей работе с ИИ

**Решение:** Проверить курс, на котором ребёнок создаёт свой проект с помощью ИИ.
**Для кого:** Родители, которым важно применение навыка на практике. Пока гипотеза.
**Основания:** [ссылки, цитаты и данные из исследования]
**Следующий тест:** Провести интервью с родителями и пробное занятие.
**Условие пересмотра:** Если этот результат не важен семьям — пересмотреть предложение.
```

После решения предложи маркетинговый блок (шаг 6).
